## 1. CI 核实：安全网是好的，只是从没通电

**问题**：19 个测试文件、约 30 个用例被 `HRBP_RUN_DB_SECURITY_TESTS` /
`HRBP_RUN_CONCURRENCY_TESTS` 门控（RLS 租户隔离、租户外键、审批竞态/崩溃一致性、
outbox 租约栅栏、工具网关、执行授权、dispatcher 并发、OAuth 竞态）。
上一轮审计把它们记为"刻意未改，待核实 CI 是否运行"。

**核实结果（比预想更糟也更好）**：

- `.github/workflows/ci.yml` **专门**准备了 RLS-bound 数据库角色（`hrbp_ci_app`，
  `NOBYPASSRLS`），并用两段内联脚本断言测试连接确实受 RLS 约束——
  **这份工作只为这些测试存在**；
- 但 job 的 `env` 一个开关都没设 → 这批用例在 CI 里同样全部 `pytest.skip`；
- **打开开关本地实测：324 passed / 1 skipped / 30.11s，全部通过。**
  用例是好的，只是从未被启用。

**修复**：

1. `ci.yml` 的 backend `env` 加上两个开关；
2. 新增步骤 *Assert the gated security/concurrency regressions actually ran*：
   单独重跑这批用例，输出里出现任何 `skipped` 即构建失败。
   只设 env 不够——开关被删掉、改名时测试会**静默**回到 skip 而全量依然绿色，
   必须让"安全网没通电"变成红灯。

**正负两向验证**：设开关 21 passed / 0 skipped；不设开关跑同一批 →
`3 skipped` 被闸门正确检出。

**仍然没跑的**：`tests/integration/test_hybrid_rag.py` 需要 Milvus，CI 无此服务。
这正是本次事故的那条链路（dense+sparse 融合）。加 Milvus 到 CI 需要
etcd+minio+milvus 三个容器，代价不小——**留作决策**，不悄悄塞进本次 diff。

## 2. 语料治理：来源级别（`SourceAuthority`）

**问题**：知识库里同时存在三类东西，系统此前对它们一视同仁——
国家法规（09/10）、第三方模板（hrtools/用友/三茅，其中手册模板的年假条款写着
"×天"占位符）、无关材料（酒店考核表、普华永道方法论）。
排序修好之后年假问题的 top-1 已正确，但 **#2 仍是酒店技能考核表**——
排序对了，语料没修好。格式过滤挡不住"别家的模板"，只有声明来源级别能。

**设计决定（每条都有理由）**：

1. **人工声明，绝不推断。** "看起来像模板"正是最不可靠的判据；判错的代价是把
   第三方条款当成本单位制度。取值只有
   `national_law / company_policy / vendor_template / reference / unknown` 五种。
2. **默认 `unknown`，不是 `reference`。** 让"没人声明过"在数据里可见，
   而不是伪装成一个已知的无害值。
3. **回填放在融合后的统一步骤**（`Retriever._attach_authority`），不在每条腿里
   select。dense 腿读 Milvus，要带新字段得**重新索引整个语料**；统一回填两条腿
   （及未来任何腿）都覆盖，代价是每次检索一条小查询。这同时避免了本项目反复
   出现的"约定只在部分地方落实"。
4. **不参与排序。** 有意为之：按级别重排是全局语义变更（一条相关度极高的
   本单位条款会被一条低相关的国家法规压下去），没有评测基线支撑前不做。
   先把"性质"给到调用方，排序留待有数据支撑时再动。

**落地**：

| 层 | 内容 |
|---|---|
| 迁移 `045_documents_authority` | 加列（建列时用临时 server_default 回填完毕后**随即删除**，保持与模型一致，避免 schema 漂移）。**纯 schema，无数据回填**——回填要写行，而迁移以非超级用户跑在 `FORCE ROW LEVEL SECURITY` 下，无租户上下文的 UPDATE 看不见也改不了任何行 |
| `scripts/classify_kb_authority.py` | 按显式映射落库（`docs/ops/kb-authority-map.json`，每条带 why）。全走 `make_tenant_session`（RLS 生效），不关 RLS 后门。幂等；映射与库对不上时**退出码 1**（映射过期必须看得见）；统计必须**提交后重查**——第一版拿改动前快照统计，报出过 `0/11 可作依据`（实际 2 份国家法规），这种"看起来合理但错误"的数字比没有更糟 |
| `scripts/import_kb_docs.py --authority` | 未来导入入库即声明；**重复导入不覆盖**既有分类（重导不应静默重置人工标注） |
| 检索层 | `RetrievedChunk.authority` 进 `to_dict()` |
| `search_policy` | 每条命中带 `source_type`（中文标签，不暴露内部取值）；**命中里没有任何权威来源时**，响应加 `authoritative_source: false` + `authority_note`，摘要前置`【注意】` |
| 工具描述 | 写明"只有本单位制度/国家法规可作依据；国家法规是法定最低标准，不等于本公司规定；模板里的示例数字不得当真"，`DESCRIPTIONS_VERSION` → `2026-09-16.2` |

**端到端验证**（真实 OAuth + HTTP）：

- 年假问题：`#1 [国家法规] 国务院令第514号 / 第五条`，无 `authoritative_source`
  字段（有真依据时不加字段，与降级标记同一约定）；
- "试用期的考核表怎么填？"：三条命中全是第三方模板 →
  `authoritative_source: false` + 明确的"不能作为制度依据"提示。

一致**：etcd v3.5.5、minio RELEASE.2023-03-20T20-16-18Z、milvusdb/milvus v2.5.0；

### 6.3 RRF 平局的来源级别裁决

**先读码确认了机制**：`fused.sort(key=score)` 是稳定排序，平局的先后由
**插入顺序**（哪条腿先产出谁）决定。原事故里国务院条例与酒店考核表的融合分
**完全相同**（0.016667 = 1/(60+0)）—— 平局是真实存在的，不是推测。

实现：`fusion.apply_authority_tie_break()`，**只在分数完全相等**的相邻分组内
按来源级别稳定重排；任何分差（哪怕 0.0001）都由相关性优先。刻意不用
"接近相等"阈值——那会让来源级别开始干预有分差的排序，是越界。
`rrf_fusion` 与 `fuse_query_variants`（policy_qa 的 query 变体路径，dict 形态）
都接入了裁决 —— 只接一处就又是"约定只在部分地方落实"。
配套改动：来源级别回填**前移到融合前**（hybrid 对两腿并集查一次），
因为裁决在排序时就要读它。

测试含一条**复刻原事故分数形态**的用例（两腿各一条、融合分同为 0.016667），
断言国家法规胜出。

**注意**：这会改变评测数字（平局的命中顺序变了）。评测基线需要重跑对账——
本轮未跑评测（需要真实的 LLM/embedding 配额），这是诚实的边界。
