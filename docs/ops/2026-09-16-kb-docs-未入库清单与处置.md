其中 `.txt` 3 个 = 本次新增的《职工带薪年休假条例》《企业职工带薪年休假实施办法》

  年假×3  休假×7   9176字符  06_hrtools_员工手册模板v3.doc            ← 制度正文模板，已转并入库
  年假×0  休假×1  14982字符  08_.../宁波贝发集团有限公司员工绩效考核手册.doc  ← 别家公司内部手册，不入库

即：**转换成本极低（88/88 成功），但可捞回的内容几乎为零**——87 个转换后不含任何休假内容，
且其中绝大多数是考核表、面谈表、签到簿一类表单。

`textutil` 的一个坑：读不了的文件**仍然返回 rc=0**，且不创建输出文件。
判断成功必须同时检查退出码和输出文件是否存在，只看退出码会把 `.xls`/`.ppt` 误判为转换成功。

## 3. 为什么 `.doc` 里的内容此前完全不可见

早期用脚本（`zipfile` + 正则）扫过这批文件，`.doc/.xls/.ppt` 一律得到 **0 字符**。
那 0 字符是**提取失败**，不是"文件里没有该内容"——`06_hrtools_员工手册模板v3.doc`
转出来后年假出现 3 次，`宁波贝发...手册.doc` 也含休假条款。

**任何基于"扫过一遍没找到"得出的覆盖率结论，都必须先确认提取是否真的成功。**
本次 113 个文件里，`.doc/.rtf` 一类确实藏有正文，只是被格式门槛挡在门外。

## 4. 治理缺口：格式过滤不是来源过滤（重点）

113 个被拒绝的文件里，混着一批**别家公司的内部制度**，仅从文件名就能看出：

- `绩效考核工作规定（联想电脑）.doc`
- `通讯－中国网通绩效考核管理制度.doc`
- `某房地产企业绩效考核制度.doc`
- `宁波贝发集团有限公司员工绩效考核手册.doc`
- `山东鲁能积成电子股份有限公司绩效考核体系.doc`
- `中信华南（集团）东莞公司绩效考核方案完整版.dot`

它们现在被挡住的原因是**格式（`.doc`）**，不是**来源**。
一旦有人为了"把资料都用起来"批量转成 `.docx`，它们会**直接通过格式校验进入知识库**。
后果是：员工问"我们公司的绩效考核怎么规定"，系统会拿**联想电脑**的规定回答，
而且带出处、看起来非常可信。

这比"查不到"危险得多。**`NO_EVIDENCE` 是诚实的；一个来自别家公司的错误引用不是。**

**建议（按优先级）**：

1. **给知识库文档加"权威等级"字段**（`国法` / `本单位制度` / `第三方模板`），
   检索时按等级加权或按场景过滤。当前 11 个已入库文档里，2 个是国法、9 个是第三方模板，
   它们现在是**等权**参与检索的——这解释了为什么"公司的年假是怎么规定的"会同时
   返回《国务院令第514号》和一个酒店考核表。
2. **把"不入库"的决定写进代码而不是靠自觉**：给导入脚本加一份显式排除清单
   （按路径或来源标记），而不是依赖"格式恰好被拒绝"这种偶然保护。
3. **第三方模板的占位符要防**：`11_hrtools_员工手册模板v3(由doc转换).txt` 里
   年假条款写的是"每满 1 年可享受 **×** 天"——模板占位符。它已入库（因为它就在
   `kb_docs/` 里，静默丢弃会重演"文件存在≠知识可用"的错觉），但检索命中时
   会把"×天"当作制度念出来。同一个坑也存在于已入库的 `03_hrtools_员工手册模板v2.docx`。
