# HRBPilot 前端设计规格

**状态：已确认，待实现规划**
**范围：桌面优先的五场景 HR 工作台**

## 1. 目标与边界

HRBPilot 前端的目标是让 HR 用户完成真实工作：管理制度知识库、提出制度问题、
处理异步分析任务、生成周报和内容，并看见系统是否可靠。它不是泛 AI 聊天页面，
也不是传统 OA 的 KPI 大盘。

前端必须如实反映当前 FastAPI 后端：真实 Hybrid RAG、异步任务、RBAC、系统健康
和评测接口可用；若历史记录、通知或数据持久化尚未由后端实现，则显示明确空状态，
不得伪造数据。

首要使用环境为 1440px 及以上桌面浏览器。375px 视图只保证登录、状态查看和轻量
问答，不承诺完成上传、长文编辑等桌面任务。

## 2. 设计方向

方向为“编辑部工作台”：信息密度与可读性兼顾，页面组织围绕“事情是什么—依据在哪里—
下一步怎么做”。参考成熟应用壳层与设计系统方法，但不复制任何第三方品牌、页面或代码。

### 视觉令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F7F7F4` | 页面背景 |
| `--surface` | `#FFFFFF` | 聚焦的阅读与编辑区域 |
| `--ink` | `#20231F` | 主文字 |
| `--muted` | `#6C716A` | 元数据与辅助信息 |
| `--action` | `#245B4D` | 主要动作、完成状态 |
| `--evidence` | `#A9652B` | 引用与证据强调 |
| `--danger` | `#B8473F` | 错误和风险 |
| `--line` | `#E3E5DF` | 分割线与低优先级边界 |

标题使用 `Noto Serif SC`，正文和表格使用 `Noto Sans SC`，数值、文件体积、状态码和
时间使用 `IBM Plex Mono`。不使用 Arial、Roboto、Inter、Space Grotesk、紫粉渐变、
玻璃拟态、悬浮机器人或伪造 KPI。

### 布局与动效

- 使用 12 列桌面栅格；长文阅读列最大约 760px。
- 顶部全局工作栏为 56px；左侧导航为 216px，浅底、细线选中，不使用厚重深色侧栏。
- 页面以主任务和辅助证据构成非对称双栏；用间距、细线和文字层级取代卡片阴影。
- 页面进入动画控制在 240ms 内；SSE 回答按文本块出现；异步任务展示可解释阶段。

## 3. 应用壳层与权限

全局导航：概览、制度问答、知识库、面谈纪要、周报、文化内容、语音洞察、质量与用量、
设置。顶部显示工作空间、命令搜索入口、系统异常入口和账户菜单。

`hr_manager` 可使用概览、制度问答、知识库、质量与用量、设置；`hrbp` 可使用全部模块。
不具备 `hrbp` 的用户仍能看见受限模块及能力说明，但主操作为锁定态；直链访问受限页显示
权限说明而不是裸 403。

全局状态共有等待、处理中、完成、警告、失败、无权限六类。错误信息必须给出用户层说明，
并在可展开区显示 request id、时间和后端诊断摘要。

## 4. 页面规格与接口映射

### 登录

对接 `POST /api/auth/login` 和 `GET /api/auth/me`。仅展示邮箱和密码；成功后进入概览。
访问令牌只保存在会话内存，刷新令牌使用受控持久化策略；页面不展示或记录敏感密钥。

### 概览

对接 `/api/ready` 与知识库列表。显示真实基础设施状态、待索引文档和三个主入口：问制度、
上传制度、新建知识库。无数据时展示下一步，不生成团队效率等未经后端支持的指标。

### 制度问答

对接 `GET /api/policy-qa/knowledge-bases`、`POST /api/policy-qa/ask`、
`POST /api/policy-qa/feedback`。

页面为 7:5 双栏：左侧为知识库选择、问题输入、SSE 回答和反馈；右侧为引用来源、命中文档、
文本摘录与匹配说明。技术匹配标签面向用户翻译为“语义相关”“条款关键词”“综合排序”，
不把向量数据库或模型参数当主信息。后端历史接口为空时，标为“当前会话不保存”。

### 知识库

对接 `POST /api/kb/create`、`GET /api/kb/list`、`GET /api/kb/{kb_id}`、
`POST /api/kb/{kb_id}/upload`、`POST /api/kb/{kb_id}/ingest`、
`GET /api/kb/{kb_id}/documents`、删除接口。

页面采用目录—详情结构。上传仅显示 `txt`、`pdf`、`docx` 和 20MB 限制；状态语义为：
`uploaded`（等待建立索引）、`parsing`（正在解析）、`indexed`（已纳入问答依据）、
`error`（索引失败）。上传完成不等于可问答；用户必须看到已索引状态。错误状态展示后端
`error_message` 并提供重试入口。

### 面谈纪要

对接 `/api/interview-digest/upload`、`/analyze`、`/progress/{task_id}`、
`/result/{task_id}`。流程固定为上传或粘贴材料、确认解析文本、发起分析、轮询进度、查看
结构化纪要。少于 50 字不提交。历史接口为空时显示服务端持久化未开放。

### 周报

对接 `/api/weekly-report/generate`、`/save`、`/{report_id}`、`/history`。页面为来源列表加
可编辑报告纸。来源不足时明确提示后端会使用示例来源；保存草稿和发布使用不同文案与确认。
后端为内存级存储时，提示重启后可能不可恢复。

### 文化内容与语音洞察

文化内容对接关键词扩展、生成和历史接口，采用输入参数与生成稿双栏。语音洞察第一版仅
接收真实后端已有文本或转写输入，展示异步进度和洞察报告；不在未支持音频上传前伪造录音
器或波形。

### 质量、用量与设置

质量页只使用真实 `/api/eval/*` 与评测接口数据。无数据时使用说明性空状态；占位评测必须
标注“不可用于业务判断”。设置页只涵盖 LLM Provider、连通性测试、当前用户角色和系统
健康摘要；绝不在浏览器中管理 API Key、JWT 或数据库密码。

## 5. 前端架构约束

实现阶段在独立 `web/` 目录中创建 React + TypeScript + Vite 应用。使用 React Router、
TanStack Query 与 CSS Variables / CSS Modules；Vite 开发代理将 `/api` 转发至现有
FastAPI 服务。SSE 使用带 Authorization Header 的 `fetch` 流读取，不能依赖原生
`EventSource`。所有请求 DTO 集中在 `web/src/api/`，角色控制集中在会话和路由层。

前端目录须在创建时先增加 `web/AGENTS.md`，明确目录责任、命名、测试和临时文件清理规则。
不引入整套第三方后台模板：可借鉴布局与无样式可访问性 primitives，但不接入模板自带的
模拟认证、模拟数据、支付、统计或无关业务模块。

## 6. 验收标准

1. `hr_manager` 能登录、创建知识库、上传、触发索引并查看真实状态。
2. 制度问答能携带 JWT 发起 SSE 请求，显示文本、错误与后端返回的真实来源。
3. 受限角色不会得到误导性可用入口，直链受限模块有明确解释。
4. 已实现页面对空、加载、失败和完成状态均有可理解的界面。
5. 不显示后端未提供的历史、指标或通知；示例数据显式标识。
6. 1440px 布局无需横向滚动；375px 可完成登录、查看状态和轻量问答。
7. 前端 lint、类型检查、构建和关键 API 适配测试通过。
