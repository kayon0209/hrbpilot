# 数据接入能力矩阵

> 依据：正式产品 UI/UX 最终实施方案 §10（四级认证与兼容矩阵）。
> 规则：**只有第四级（可使用）才能宣称「已兼容」**；其余等级必须如实标注当前状态。
> 本矩阵随每次认证状态变化更新；不得用「已连接」掩盖未验证能力。

## 四级认证定义

| 等级 | 标签 | 含义 |
|---|---|---|
| 1 | 准备接入 | 完成鉴权、权限、事件、文件和错误模型映射 |
| 2 | 配置测试中 | 完成测试企业内收发、撤权、重试、限流、重复事件测试 |
| 3 | 企业试用中 | 在真实租户的单一业务场景验证数据去向和用户理解 |
| 4 | 可使用 | 具备监控、幂等、重放、凭据轮换、暂停、撤销、审计和保留策略 |

## 安全基线（每个渠道接入时必须满足）

- 最小 scope；授权前向管理员展示用途与数据去向。
- 凭据租户级加密或外部密钥管理，凭据永不出现在任何 API 响应中。
- 不默认读取群聊历史、私人会话或全邮箱（企业邮箱接口拒绝整箱邮件读取）。
- 暂停立即停止新同步；撤销不可逆且记录时间与原因。
- 同步预览必须在首次写入业务工作区前由管理员确认。

## 实施顺序原则

首个生产认证平台由试点客户日常使用量最高且官方能力满足最小权限的平台决定（方案 §二十一）；不按技术容易程度排序。
